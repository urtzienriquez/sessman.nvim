==============================================================================
INTRODUCTION                                                         *sessman*

A session has a name and belongs to a project directory (or is global). At
any time it is

  running   an Nvim server your terminal |:connect|s to; it survives closing
            the terminal, keeping buffers, undo, |:terminal|s and jobs, or
  saved     a |:mksession| file (plus an optional |shada| file) that survives
            reboots, or both.

Going to a session jumps to it when it runs, and otherwise restores it into a
fresh server. Saving is always explicit. Think of tmux + tmux-resurrect, made
of Nvim's own |client-server| parts.

The project is only an anchor, fixed when the session is created: the git
root of the working directory, or the directory itself. The working directory
is ordinary session state, so a "manuscript" session can belong to a repo
while working in its manuscript/ folder.

Requires Nvim 0.12+ (|:connect|) on a Unix-like system. Nothing but two
commands and an autocommand is defined at startup.

Tip: with Nvim 0.13+, `silent detach!` in your config keeps any plain nvim
alive when its terminal closes, too (|:detach!|).

==============================================================================
COMMANDS                                                    *sessman-commands*

                                                                    *:Session*
:[mods] Session         Open the session buffer |sessman-buffer| in a split at
                        the top, spanning the full width (at the bottom with
                        'splitbelow'), like fugitive's `:Git`. [mods] such as
                        |:vertical|, |:botright| or |:tab| change that. If
                        it's already visible it is focused.

:Session {target}       Go to {target} |sessman-targets|: jump to it if it's
                        running, restore it if it's saved, and create it if
                        it's neither (as |:edit| does for files).
                        A session you leave keeps running. A plain nvim you
                        leave is stopped, unless that would lose something:
                        unsaved changes or a running |:terminal|. Then it
                        keeps running under "Unnamed nvim".

:Session -              Go to the running session you left most recently.

                                                                *:SessionSave*
:SessionSave            Save the current session to its file. Its ShaDa file
                        is written too, if it has one. A session that isn't
                        running comes back as it was at its last save.

:SessionSave[!] {target}
                        Make this plain nvim a session named {target} and
                        save it. Fails if {target} is already saved, unless
                        [!] is given. A session's name can't be changed.

==============================================================================
TARGETS                                                      *sessman-targets*

    name              a session of the project you are in, else a global one;
                      new sessions go to the project you are in
    global/name       a global session
    project/name      a session of the project with that directory name
    ~/path/name       a session of the project at that path

The project you are in is the git root of the working directory, or the
working directory itself outside a git repository.

Completion lists every session, fuzzily matched, so `:Session <Tab>` works as
a fuzzy session picker.

==============================================================================
SESSION BUFFER                                                *sessman-buffer*

`:Session` shows every session by state, like fugitive's summary buffer:
>
    Session: manuscript
    Project: ~/Documents/thesis
    Help:    g?

    Running (3)
      ~/Documents/thesis
        coding      never saved
        manuscript  current, saved 2h ago
      ~/Documents/GitHub/sessman.nvim
        coding      saved 1h ago, in lua/

    Saved (2)
      ~/Documents/thesis
        review      saved 3d ago
      global
        notes       saved 5d ago

    Unnamed nvim (1)
      ~/Downloads  plain nvim
<
Session:        the session you are in, or "none".
Project:        the project you are in: where new sessions go.
                In an nvim that isn't a session yet, a line below the
                header shows it (`~/dir  current`); `:SessionSave {name}`
                makes it a session, which then appears under Running.
Running         sessions with a live server: going there is instant, and
                everything (buffers, undo, terminals) is as you left it.
Saved           sessions that only exist as files: going there restores
                them as they were at their last save.
Unnamed nvim    other nvim instances that aren't sessions (started with a
                plain `nvim`). You can go to them, or kill them.

Inside a section, sessions are listed under their project's path (the
project you are in first, "global" last), so equal names in different
projects are told apart.
A running session's working directory is shown when it isn't the project
root. The buffer refreshes when entered; |:edit| re-reads it.

                                                                *sessman-maps*
<CR>        Go to the session under the cursor.
s           Save it (also a running session elsewhere). On the current
            unnamed nvim, start `:SessionSave `.
S           Save it and start or update its ShaDa file.
X           Kill it: stop its server, keep its files. Killing the current
            session moves you to the previous one, or quits.
D           Delete it: remove its files, and kill it if it runs.
co<Space>   Start `:Session ` on the command line.
cs<Space>   Start `:SessionSave ` on the command line.
)  (        Next/previous session.
]]  [[      Next/previous group.
gq          Close the buffer.
g?          Show this help.

==============================================================================
CONFIGURATION                                                 *sessman-config*

*g:sessman_dir*   Where sessions are saved.
                Default: `stdpath("data") .. "/session"`
>lua
    vim.g.sessman_dir = vim.fn.expand("~/sessions")
<
Session files for a project live in a directory named after its path, with
"/" replaced by "%"; global ones in "global/". Sessions are plain
|:mksession| files, so 'sessionoptions' decides what they contain.

No mappings are defined; for instance: >lua
    vim.keymap.set("n", "<leader>ss", "<Cmd>Session<CR>",
      { desc = "Session list" })
    vim.keymap.set("n", "<leader>sp", "<Cmd>Session -<CR>",
      { desc = "Previous session" })
    vim.keymap.set("n", "<leader>sl", function() require("sessman").pick() end,
      { desc = "Pick a session" })
<
Keep `require()` inside the function, as above, so sessman still loads only
when the map is used.

Sessions start without a UI; see |sessman-headless| for config (like ui2)
that needs one.

==============================================================================
LUA API                                                          *sessman-api*

require("sessman") ~

  go({target})         Same as `:Session {target}`.
  save([{target}], [{opts}])
                       Same as `:SessionSave`. {opts}: `bang`, `shada`.
  pick()               Choose a session with |vim.ui.select()|, and so with
                       any picker that replaces it.
  list()               All sessions: tables with `project` (false when
                       global), `name`, `file`, `sock`, and `saved`,
                       `running`, `current`, `cwd`, and `unmanaged` (an
                       unnamed nvim) when true.
  current()            The current session, or nil in a plain nvim.

*g:sessman_session* is `{ project = ..., name = ... }` inside a session, e.g.
for a statusline.

==============================================================================
HEADLESS START                                              *sessman-headless*

A session restored or created by `:Session` starts as a headless Nvim: your
config runs before your terminal |:connect|s, so no UI is attached yet
(`#vim.api.nvim_list_uis() == 0`). Config that needs a UI at startup won't
see one. For example `require("vim._core.ui2").enable()` does nothing
without a UI, and the command line falls back to the classic one.

Run such config on |UIEnter| when Nvim starts without a UI: >lua

    local function ui2() require("vim._core.ui2").enable({}) end
    if #vim.api.nvim_list_uis() > 0 then
      ui2()
    else -- headless start, e.g. a sessman session: wait for the first UI
      vim.api.nvim_create_autocmd("UIEnter", { once = true, callback = ui2 })
    end
<
A plain `nvim` behaves as before. Sessions made with `:SessionSave {name}`
from a plain nvim are not affected: that nvim started with a UI.

==============================================================================
INTERNALS                                                  *sessman-internals*

A running session listens on a socket in `stdpath("run") .. "/sessman/"` and
keeps a small status file next to it (working directory, pid, when it was
last left), so listing never waits on a busy server. Restoring runs
`nvim --headless --listen {socket}` with the session and ShaDa files, then
|:connect|s to it.

The server half is adapted from servery.nvim
(https://github.com/wurli/servery.nvim, MIT, (c) servery.nvim authors).
